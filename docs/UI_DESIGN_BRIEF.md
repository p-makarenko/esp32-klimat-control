# Бриф на редизайн веб-інтерфейсу — Klimat Kontrol (ESP32-S3)

Цей документ підготовлений для передачі дизайнерській AI-моделі (наприклад, Gemini 4 Neon) для створення сучасної, єдиної та легкої дизайн-системи (HTML-макет + CSS), яку потім буде інтегровано в прошивку ESP32-S3.

---

## 1. Про проєкт

- **Назва:** Klimat Kontrol — автономна система клімат-контролю та автоматизації приміщення/теплиці на базі **ESP32-S3**.
- **Мова інтерфейсу:** українська.
- **Основні пристрої користування:**
  - Смартфон (iOS / Android) — основний сценарій (перевірка статусу, керування слайдерами, перегляд графіків).
  - Ноутбук / ПК — детальні налаштування, графіки, OTA-оновлення.
- **Поточний стан:** навігацію вже уніфіковано (єдина липка верхня панель `.topnav` у `src/web_common.h`), але візуальний стиль сторінок застарілий і різнорідний (суміш світлого дизайну 2015 року, inline-стилів та темної сторінки `/update`).

---

## 2. Критичні технічні обмеження (ОБОВ'ЯЗКОВО ВРАХУВАТИ)

1. **Без важких фреймворків та зовнішніх CSS-бібліотек:**
   - Ніякого Bootstrap, Tailwind CDN, FontAwesome CDN чи Google Fonts (`@import` шрифтів уповільнює або блокує завантаження в локальній Wi-Fi мережі без інтернету).
   - Використовувати системний стек шрифтів (`system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`) та легкі inline SVG-іконки або мінімалістичні емодзі.
2. **Обмеження розміру CSS:**
   - Весь HTML/CSS збирається в оперативній пам'яті ESP32-S3 (`String` у C++).
   - Цільовий обсяг спільного CSS: **до 5–7 КБ** (чистий CSS із CSS-змінними `:root`, без зайвих повторів).
3. **Єдині зовнішні скрипти:**
   - `Chart.js 4.4`, `hammerjs 2.0.8`, `chartjs-plugin-zoom 2.0.1` підключаються **лише** на сторінках `/history` та `/energy`.
4. **Адаптивність (Mobile-first):**
   - Брейкпоїнти: мобільний (`≤ 480px`), планшет (`≤ 768px`), десктоп (`max-width: 1200px`).
   - Для `input`, `select`, `textarea` на мобільних обов'язково `font-size: 16px` (запобігає автозуму в iOS Safari).
5. **Чиста архітектура без C++:**
   - На етапі дизайну **не редагувати C++ файли**. Створити автономний HTML-прототип (один `.html` файл, який можна відкрити в браузері) із демонстрацією всіх компонентів та ключових екранів.

## 4. Виявлені проблеми поточного UI/UX

1. **Змішання стилів:** більшість сторінок світлі (`#f0f0f0` + білий контейнер), а `/update` темний (`#1a1a2e`), частина елементів на `/ota` також стилізована під темну тему.
2. **Inline-стилі:** у багатьох `.cpp` файлах кольори, відступи та фони прописані прямо в `style='...'`, через що зміна теми ламає контрастність.
3. **Перевантажена сторінка `/settings`:** понад 15 секцій налаштувань потребують чіткої групованої навігації (вкладки або згортані блоки).
4. **Дублювання функцій Wi-Fi:** існують `/wifi`, `/wifi-settings` та секція Wi-Fi всередині `/settings`.
5. **Застарілий візуал:** плоскі яскраві Material-кнопки 2014–2016 років (`#4CAF50`, `#2196F3`, `#f59e0b`), різкі тіні, відсутність візуальної ієрархії між головними метриками та другорядними елементами.

## 5. Що має містити результат від дизайнерської моделі

Потрібен **один автономний файл-макет** (наприклад, `docs/ui_prototype.html`), який можна відкрити локально в браузері (десктоп + мобільний режим DevTools) і який містить:

1. **Єдину дизайн-систему на CSS-змінних (`:root`):**
   - Пропонована концепція: сучасний **IoT / Smart Home Dashboard** (темна тема або перемикач Dark/Light з пріоритетом чистої контрастної палітри — як у Home Assistant / сучасних інженерних панелях).
   - Токени кольорів: фон, поверхня картки, акцент, успіх (норма), попередження, критична аварія, текст основний/вторинний, рамки.
2. **Повний набір UI-компонентів (UI Kit):**
   - **Навігація (`.topnav`):** липка верхня панель з горизонтальним скролом на мобільному, активним станом та чіткою типографікою (плюс гармонійний вигляд головної сторінки без дублювання меню).
   - **Картки метрик (KPI Cards):** велике значення, одиниці виміру, індикатор статусу (онлайн / норма / помилка датчика), колірний акцент для Температури, Вологості, CO2, Енергії.
   - **Індикатори виконавчих механізмів:** Насос (A), Вентилятор (B), Витяжка (C) — візуальна шкала завантаження 0–100%.
   - **Аварійний банер:** чітке, помітне попередження (наприклад, «Відсутність 220В»).
   - **Кнопки:** Primary, Secondary, Success, Warning, Danger, Ghost/Outline, компактні швидкі кнопки.
   - **Елементи керування:** кастомні слайдери (range), перемикачі (toggle switch), сегментні кнопки режимів (Авто / Ручний), вкладки (Tabs), акордеон для налаштувань.
   - **Форми:** інпути, селекти, підказки (tooltips), групування полів у сітку.
   - **Консоль команд:** термінальний блок виводу `#commandOutput` + рядок вводу + швидкі команди.
   - **Прогрес-бар (OTA) та зона ризику (Factory Reset).**
3. **Інтерактивне прев'ю 3–4 ключових екранів у прототипі** (перемикання вкладок прямо в `ui_prototype.html` без бекенду):
   - Головна (`/`)
   - Керування (`/control`)
   - Налаштування (`/settings` — приклад із вкладками/секціями)
   - Енергія або OTA (`/energy` / `/ota`)

## 6. Готовий промпт для запуску дизайнерської моделі

Скопіюйте цей текст у новий чат (або виконайте прямо тут після перемикання на дизайнерську модель):

> Прочитай файл `docs/UI_DESIGN_BRIEF.md`.
> На основі цього брифу розроби сучасний, чистий та зручний дизайн веб-інтерфейсу для системи клімат-контролю **Klimat Kontrol (ESP32-S3)**.
>
> **Вимоги до результату:**
> 1. Створи один автономний файл `docs/ui_prototype.html`, який можна одразу відкрити в браузері на ПК та в мобільному режимі.
> 2. Весь спільний CSS має бути виділений в окремий чіткий блок `<style id="common-css">`, не перевищувати ~6 КБ у немінімізованому (або мінімізованому) вигляді, використовувати CSS-змінні `:root` та не покладатися на зовнішні бібліотеки чи CDN-шрифти.
> 3. У прототипі зроби інтерактивне перемикання між демо-екранами: **Головна**, **Керування**, **Налаштування**, **OTA / Енергія**, щоб я міг оцінити всі компоненти в дії (картки датчиків, слайдери, вкладки налаштувань, консоль команд, аварійний банер, прогрес-бар, адаптивність на 375px і 1280px).
> 4. Додай перемикач **Темна / Світла тема** (через `data-theme`), щоб я міг обрати, яка краще виглядає для щоденного користування.
> 5. НЕ редагуй жодних C++ файлів у `src/` — зараз потрібен лише дизайн-прототип та готовий CSS для подальшої інтеграції.
